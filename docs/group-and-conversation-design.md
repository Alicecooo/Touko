# 分组与对话设计

## 当前模型

Touko 中的分组是 Bot 的归类容器。分组用于管理 Bot 的归属、排序和成员关系，不代表聊天会话，也不保存群聊消息。

每个 Bot 使用自己的直接对话和任务线程。Bot 之间的协作通过明确的任务委派和结果回传完成；系统不会因为 Bot 同属一个分组而自动互相发言、互相 @ 或启动轮次。

## 已移除的群聊模型

旧实现把分组同时当作群聊载体，并在分组上叠加了成员运行位置、默认回复者、自动回复策略、轮次限制、共享简报和群聊工作目录等运行时配置。这些配置把 Bot 自身行为、会话状态和分组管理耦合在一起，导致：

- Bot 之间出现非用户触发的消息和异常 @；
- 同一个 Bot 的多个对话与群聊线程重复表达同一状态；
- 分组删除、成员变更和消息恢复需要协调器、队列和运行时锁共同维护；
- 设置页出现无法解释的群组轮次、共享简报和批量 Bot 参数。

群聊创建、群聊消息路由、群聊轮次和群聊运行时配置已从公开接口、前端入口和服务端协调器移除。旧数据只在导入或升级路径中保留必要的兼容解析，兼容代码不会重新启用群聊功能。

## 分组管理原则

- 分组只管理 Bot 的归属和成员关系。
- 模型、审批、推理强度、记忆和运行目录等参数属于 Bot 或具体任务线程。
- 分组只保留一个“分组管理”入口，删除操作使用统一的分组菜单。
- 不在分组层提供批量运行参数、共享简报或群聊专属设置。
- 新建 Bot、打开 Bot 对话和管理分组是三个独立操作，避免重复入口和重复说明。

## 持久化目录

应用默认数据目录是用户目录下的 `~/.touko`。旧的 `~/.openmausbot` 和 `~/.opengrokbot` 目录只作为一次性迁移来源读取。`OMB_DATA_DIR` 继续作为内部和测试环境的兼容变量，避免破坏既有启动脚本；它不改变产品默认目录名称。

## Webhook

Touko 不再提供项目 Webhook 配置、Webhook API 或对应的运行时路由。搜索结果中出现的第三方 Webhook 示例或通用 MCP 工具不属于 Touko 的产品入口，不能据此恢复 Webhook 功能。
